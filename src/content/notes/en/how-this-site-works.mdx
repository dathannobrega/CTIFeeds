Threat research is only useful if other people can read it and reuse its data. This site is
built around that idea: every post is written for humans, and every campaign also ships as
data that a SIEM, an EDR or a CTI platform can ingest without anyone copying values out of
HTML.

## Static pages, typed content

The site is plain HTML generated by [Astro](https://astro.build/) from MDX files kept in Git.
There is no database, no login, no comments and no third-party script at runtime, which keeps
the attack surface close to zero and pages fast.

Each post has a frontmatter schema (title, language, tags, ATT&CK IDs, TLP). If a required
field is missing, or a post claims anything other than TLP:CLEAR, the build fails. Drafts stay
out of production builds.

## Two languages, one canonical

English is the canonical language and Brazilian Portuguese mirrors it. Every page lives under
its own prefix (`/en/` and `/pt-br/`), and both versions of a post share a translation key:

- each page declares itself and its sibling with reciprocal `hreflang` tags;
- a post without a translation emits no `hreflang` for the missing language and shows a
  notice instead of machine-translated filler;
- the root URL is a language chooser and the `x-default` target, not a blind redirect.

Each language has its own RSS feed (`/en/rss.xml`, `/pt-br/rss.xml`) and JSON Feed, so readers
only get posts in the language they follow.

## IoCs: one source, several formats

A campaign is described by one YAML file in `data/campaigns/`. That file is the only place
indicators are written down; everything else is generated at build time:

```yaml
id: 2026-10-example
tlp: CLEAR
first_seen: 2026-09-01
last_seen: 2026-09-28
source: personal honeypot
attack: [T1110, T1021.004]
post: /en/research/example/
iocs:
  - { type: ipv4, value: 192.0.2.10, confidence: high, first_seen: 2026-09-02 } # RFC 5737
```

From it the build produces:

- `/iocs/<campaign>.csv` with the same columns for every campaign (type, value, first and
  last seen, confidence, TLP, campaign, post URL, source);
- plain lists, one value per line, ready for blocklists;
- a STIX 2.1 bundle with `campaign`, `indicator`, `attack-pattern` and `relationship`
  objects, validated against the OASIS schemas in CI;
- an index and a `CHECKSUMS.sha256` file.

Generation is deterministic: STIX IDs are derived from the data, so a rebuild with the same
YAML produces the same bytes and the same checksums.

In the text, indicators are always defanged (`hxxp`, `[.]`). The raw values only exist in the
downloadable files, where tools need them. A post-build check scans every HTML page and fails
if a raw indicator leaks into the prose.

## Checks before anything is published

The build is the only path to production, and it refuses to finish when:

- an indicator is malformed, duplicated or outside the campaign period;
- anything is not TLP:CLEAR;
- a forbidden term (kept outside the repository) appears in content or data;
- an image still carries EXIF metadata;
- a campaign post is missing one of its sections: executive summary, timeline, technical
  analysis, ATT&CK, IoCs, detections and recommendations;
- `hreflang` links are not reciprocal, or a post's HTML, CSS and JS exceed 100 KB.

## Delivery

The output is served by Cloudflare Workers static assets. A `_headers` file sets a Content
Security Policy without `'unsafe-inline'` (syntax highlighting uses CSS classes instead of
inline styles), HSTS, `nosniff` and a strict referrer policy. Every pull request gets a
preview URL, and a merge to `main` deploys.

The source code of the site is public, so if you spot something wrong, an issue or a pull
request is welcome.
